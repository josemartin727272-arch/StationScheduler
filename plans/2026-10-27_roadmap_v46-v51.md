## Global constraints (every phase)

- One phase = one version = one deploy. Amihay tries it on the iPad before the next phase starts.
- Before any deploy that changes stored data (config / archive shape): Amihay
  makes a full backup (📁 Archive → 📤 Backup all) on **every** device first.
- Every stored-data change goes through `migrateConfig` (or an archive
  migration of the same kind) and gets a test that loads an **old** v45 backup
  and checks nothing is lost.
- Nothing ever leaves the device unless Amihay presses a button that says so
  (the guide promises "no cloud"; changing that is decision D1).
- TDD: each feature's test is written and seen failing first.
- Bump `CACHE` in `service-worker.js` on every deploy; new files go into `ASSETS`.
- All user text in he / en / es; the in-app GUIDE is updated in the same phase.
- Push with the repo owner's gh login (the active keychain account gets 403):
  `T=$(gh auth token -u josemartin727272-arch); git -c credential.helper= -c "credential.helper=!f(){ echo username=x-access-token; echo password=$T; }; f" push origin main`
- After deploy: live `service-worker.js` shows the new version and live
  `index.html` is byte-identical to local.
